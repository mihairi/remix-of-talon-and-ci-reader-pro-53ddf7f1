# Architecture rules
- Deliver the standalone Python OCR server as a versioned source archive; keep processing and API logic there, not in the React application, because OCR requires native Python dependencies.
- Use local label-anchor extraction and field validation before optional model fallback; reject label translations and detected redacted fragments as values, retain anchored address-subfield evidence and explain skipped routing; send only bounded unresolved-field crops, never the full page, to avoid label leakage and fabricated masked data.
- Keep field values backward-compatible and return provenance in a separate field_metadata map; unknown model confidence must remain null, never inferred from validation or the earlier OCR score.
- Configure accent normalization and observed-text review thresholds in the Python service's shared JSON; preserve original OCR scores and structured-field validation so spelling tolerance never fabricates confidence or bypasses identity checks.
- Represent confirmed address-subfield absence as an empty value with explicit local-rule status and decision confidence, separate from OCR recognition scores, so routing skips absent fields without inventing text.
- Measure Python activity wall time per request with a monotonic clock, accumulating retries and failed model calls; report lock waiting separately and exclude debug persistence from processing totals.
- Preload Paddle models at application startup; expose shared model/CPU/orientation settings, retain compatible Latin recognition, and choose performance defaults only after sample field comparison; time OCR substages without changing recognition results.
- Run same-model FP32 ONNX/OpenVINO through pinned PaddleX preprocessing and decoding adapters; crop only reliable enclosing borders and skip page orientation only after upright anchor evidence, counting uncertain retries, because acceleration must retain field and redaction behavior.
